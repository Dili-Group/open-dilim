# 3. Trách nhiệm từng module

| Folder | Vai trò | Ghi chú quan trọng |
|--------|---------|--------------------|
| **bootstrap** | Composition root. Nạp env, dựng DI, register adapter/tool/skill, khởi động gateway + worker pool. | Nơi DUY NHẤT wiring. Đổi broker/adapter chỉ sửa ở đây. |
| **config** | Hằng số: provider, model, effort, maxTokens, số worker, prompt gốc. | `PROVIDER` (anthropic\|gemini) + `MODEL` chọn model của provider đó. `effort=high`, stream + maxTokens 64000. |
| **types** | Type chung: `Envelope` (có `channel` — khóa định tuyến; `senderId` chưa resolve vai), `AgentResult`, `Tool`, `ChannelAdapter`. `identity` = struct `{channel, senderId, role, userId?, customerId?}`, KHÔNG string. | Core chỉ làm việc với Envelope, không biết channel gì. `userId` (nhân viên) / `customerId` (đại lý) = handle act-as, optional theo vai. |
| **message-ingest** | INPUT. Gateway nhận raw → `factory.create(channel).ingestor.parse()` → Envelope → ACK 202 → push queue. `channel` lấy từ path `/webhook/:channel` (chưa đăng ký Ingestor → 404); group thì set `addressedToAgent` = có mention @agent. | ACK ≠ answer. Không đụng LLM ở đây. `channel`/`isGroup` chỉ đổi luồng, chưa cấp quyền. Group không mention → chỉ ghi history, không chạy agent. |
| **broker** | Đệm & vận chuyển — **Redis Streams**. `queue` = ingress (consumer group: ack, retry, DLQ qua PEL). `pubsub` = broadcast fan-out. | Interface ẩn implementation → đổi sang Kafka/NATS sau không sửa core. Dùng chung Redis với short-term memory + order-lock. |
| **worker** | PROCESSING. Consume queue → dedupe (idempotency) → order-lock theo `conversationId` → `registry.resolve(resolveAgentType(channel))` → chạy root agent → emit AgentResult. | Scale ngang = thêm worker. 1 message/lúc/phòng (chống đua state group). Chạy được vài phút/msg. |
| **agents** | `router` map channel → `agentType`; `registry` map `agentType` → root agent (operations/dealer/personal/boss). Root agent = `RootAgentProfile` (DATA); bộ máy chạy lượt chung ở `runtime/build-agent.ts`: `sub-router` chọn sub-agent → assemble context → loop `while(tool_use)`. | Thêm agent = 1 file `roots/` + 1 dòng register + 1 dòng bảng channel. Channel chưa map → default agent. Không có sub-agent → không tốn lượt LLM định tuyến. |
| **llm** | Tách lời gọi model khỏi loop. `LLMProvider` interface + registry chọn provider theo config; mỗi provider (Claude, Gemini) 1 file. `Embedder` interface (gemini-embedding-001) cho memory dài hạn. | Agent loop KHÔNG biết provider nào — chỉ gọi `provider.chat/stream`. Thêm provider = 1 file + 1 dòng register. `Embedder` swap Gemini↔self-host không sửa memory core. |
| **tools** | Hàm agent gọi. Registry + JSON schema + runner. Phân loại READ (auto) / WRITE (confirm) / ESCALATE. Agent = deputy gọi hệ vận hành THAY user. | **Danh tính KHÔNG vào schema.** Tool chỉ nhận tham số nghiệp vụ (mã đơn, ngày...). Act-as handle (`user_id` nhân viên / `customer_id` đại lý) bind từ `identity` server-side (closure lúc dựng tool cho request), KHÔNG từ tham số LLM sinh → chống confused-deputy (xem [mục 4](./04-agent-routing.md)). |
| **workflows** | SOP nhiều bước = state machine. intake → check → propose → **confirm gate** → execute. | Dùng cho quy trình cứng (refund/hủy...), khác agent loop hỏi-đáp. |
| **approvals** | Human-in-the-loop. Gate suspend workflow → lưu pending → phát yêu cầu duyệt → resume khi có reply. | Async: KHÔNG block. 2 tầng: customer-confirm & staff-approve. |
| **scheduler** | CRON. Poller quét job đến hạn (index `next_run_at`) → CAS claim → dựng Envelope `source=cron` → ghi history phòng → push broker ingress → tái dùng pipeline. Job def ở Postgres. | Không path xử lý mới. Fire-once (CAS trên `next_run_at` + idempotent `msgId`). KHÔNG bypass quyền (vai resolve từ `job.identity`). Miss-fire bắn bù 1 lần. |
| **context** | Sở hữu **thứ model thấy 1 lượt**: prompt nền + catalog skill + khối memory → `system`; history → `messages`. Root agent gọi `assembleTurnContext` rồi mới vào loop. | Không có module này thì skills/memory không có chỗ cắm. Ngân sách [§7](./07-memory.md): history KHÔNG bị cắt để nhường memory; khối memory có cap riêng. Nhận `MemoryScope` từ wiring, KHÔNG tự derive. |
| **skills** | Mỗi skill 1 folder: `SKILL.md` (frontmatter+body) + `references/**`. Selector chọn theo intent, loader inject. | Progressive disclosure: chỉ `description` ở context mặc định; body/references load khi cần (tool `use_skill`/`use_reference`). Non-dev sửa, không deploy. Frontmatter `agents: dealer` giới hạn skill cho root agent nào — vắng khoá = mọi agent; lọc CẢ catalog lẫn `use_skill`/`use_reference`, tên agent sai thì bootstrap throw. |
| **broadcast** | OUTPUT. `publisher` push AgentResult lên topic. `factory` chọn broadcaster theo channel subscriber. `subscribers` cho fan-out. | Broadcast theo channel của SUBSCRIBER. Direct → DM user; group → topic phòng (mọi member), @ lại người hỏi. |
| **state** | NGẮN HẠN: Redis buffer N turn theo `conversationId` (turn gắn `senderId`); vượt ngân sách ký tự → compactor nén phần cũ thành rolling summary (theo PHÒNG, không cần scope). DÀI HẠN: memory distill→embed(gemini)→pgvector, recall top-K theo `user_id`; đường ghi là 1 writer / 1 `DistillSpec` (`MemoryWriterRegistry`), worker tra theo agent vừa chạy. Pending theo phòng. | Xem [mục 7 Memory](./07-memory.md). Long-term filter `user_id` (tenancy). `pending_action` giữ write chờ confirm + idempotency + `requesterId`. |
| **auth** | Verify webhook/token. Resolve `senderId` → vai (nhân viên/đại lý/guest) → dựng `identity` struct (`userId` từ `user_binding`, `customerId` derive `group_map`). Permission gate tool nguy hiểm. | `identity` KHÔNG để LLM/client tự quyết → chống bypass. Resolve vai ([mục 5](./05-message-lifecycle.md)) LUÔN chạy trước agent. Channel chọn agent, `identity` mới quyết quyền — agent vẫn gate từng tool theo vai. |
| **observability** | Audit log bắt buộc: conversations, tool_calls, pending_actions, handoffs. | + logger + metrics. |
